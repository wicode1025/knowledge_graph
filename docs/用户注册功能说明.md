# 用户注册功能

## 功能概述

系统提供完整的用户注册功能，采用六步向导式设计，引导用户逐步完成账户创建和个人信息录入。注册流程涉及auth_user、household_v2、housing_info、income_info、device_v2五张数据库表，确保用户数据完整入库。

## 注册入口

在登录界面中，未注册的游客用户可通过点击页面底部的"立即注册"超链接，跳转至注册界面。系统路由守卫允许未认证用户访问注册页面，已登录用户访问注册页面时将自动重定向至首页。

## 六步注册流程

系统采用分步式向导设计，以进度条和左侧步骤指示器直观展示注册进度。每步仅展示当前需要填写的字段，已完成的步骤以绿色对勾标记，降低了用户一次性面对大量输入项的心理负担。

### 第一步：账户信息

用户需输入以下字段：

| 字段 | 说明 | 校验规则 |
|------|------|----------|
| 用户名 | 用于登录系统 | 不能为空，需在3-20个字符之间 |
| 密码 | 账户登录密码 | 长度不少于6位 |
| 确认密码 | 再次输入密码 | 必须与密码字段一致 |
| 真实姓名 | 用户真实姓名 | 不能为空 |

前端JavaScript代码对用户输入进行实时约束校验。若用户输入格式不符合要求，表单底部将显示红色错误提示信息，明确告知用户具体的错误原因并引导用户修正。所有字段格式校验通过后，用户点击"下一步"按钮进入基本信息填写步骤。

### 第二步：基本信息

本步骤收集用户的个人基本信息，各分类字段的下拉选项均来源于系统数据库中的选项字典表（option_dict），学历等级遵循GB/T 4658-2006《学历代码》国家标准，确保了数据分类的规范性和一致性。

| 字段 | 输入方式 | 选项来源 |
|------|----------|----------|
| 性别 | 下拉选择 | 男 / 女 |
| 出生年份 | 数字输入 | - |
| 学历 | 下拉选择 | 小学及以下/初中/高中/中专/大专/高职/本科/硕士研究生/博士研究生 |
| 婚姻状况 | 下拉选择 | 未婚/已婚/离异/丧偶 |
| 职业 | 下拉选择 | 国家机关/事业单位人员/企业管理人员/专业技术人员等12个选项 |
| 联系电话 | 文本输入 | - |
| 城乡分类 | 下拉选择 | 城镇/农村 |
| 日常作息 | 下拉选择 | 早出晚归(朝九晚五)/白天在家/自由职业/夜班/退休在家 |

用户至少需选择性别方可进入下一步，点击"上一步"按钮可返回修改账户信息。

### 第三步：住房信息

本步骤收集用户的住房基本情况：

| 字段 | 输入方式 | 选项来源 |
|------|----------|----------|
| 住房类型 | 下拉选择 | 自有商品房/租赁住房/自建房/单位宿舍/保障性住房/别墅排屋 |
| 建筑面积 | 数字输入 | 单位：平方米 |
| 卧室数 | 数字输入 | 单位：间 |
| 客厅数 | 数字输入 | 单位：间 |
| 详细地址 | 文本输入 | - |

用户至少需选择住房类型方可进入下一步。

### 第四步：添加设备

本步骤允许用户从系统预设的24种常见家用电器中选择自己家中拥有的设备。设备按功率从高到低排列，以网格形式展示，每个设备卡片显示设备名称和额定功率。用户可多选设备，已选设备以深色高亮标识，底部实时显示当前已选设备数量。

设备数据来源于device_type_config表，包含空气调节、厨房电器、清洁卫生、影音娱乐、办公数码、照明六大类别共40种电器，注册页面默认展示使用频率最高的24种。

### 第五步：收入信息

本步骤收集用户家庭收入状况：

| 字段 | 输入方式 | 说明 |
|------|----------|------|
| 个人年收入 | 数字输入 | 单位：元 |
| 家庭年收入 | 数字输入 | 单位：元 |
| 收入来源 | 下拉选择 | 工资性收入/经营性收入/财产性收入/养老金/转移性收入/多种来源 |
| 经济自评 | 星级选择 | 1-5星，点击选择 |

### 第六步：注册提交

用户确认信息无误后点击"完成注册"按钮，系统执行以下后端处理流程：

1. **用户名查重**：系统调用注册接口，在auth_user表中检查用户名是否已存在。若用户名已被占用，后端返回错误信息并提示用户重新输入；若用户名未被占用，则在auth_user表中创建新用户账户，密码采用SHA-256哈希算法进行单向加密存储，确保即使数据库泄露也无法获取用户明文密码。

2. **创建用电账户**：系统自动生成全局唯一的用电账户标识（household_id），在household_v2表中创建对应的用电用户记录，并通过Django ORM的OneToOneField建立auth_user与household_v2的双向关联。

3. **写入基本信息**：调用基本信息更新接口，将用户在前五步填写的性别、出生年份、学历、婚姻状况、职业、联系电话、城乡分类、日常作息、详细地址等字段写入household_v2表。

4. **写入住房信息**：调用住房信息更新接口，将住房类型、建筑面积、卧室数、客厅数等字段写入housing_info表，通过外键关联至对应的household记录。

5. **写入设备偏好**：遍历用户在第四步勾选的设备列表，逐一调用设备添加接口，为每台设备在device_v2表中创建记录，同时根据设备类型预设参数自动计算额定功率、预期使用寿命和损坏概率等指标。

6. **写入收入信息**：调用收入信息更新接口，将个人年收入、家庭年收入、收入来源和自评经济等级写入income_info表。

7. **自动登录**：全部数据写入完成后，系统自动生成JSON Web Token（JWT）令牌，采用HS256算法签名，有效期7天。将用户认证信息（token、用户名、角色、用电账户ID）存入浏览器本地存储，并通过路由跳转将用户导航至系统首页。

## 数据存储架构

注册流程涉及以下数据库表：

| 数据库表 | 存储内容 | 关联关系 |
|----------|----------|----------|
| auth_user | 用户名、密码哈希值、邮箱 | Django内置用户表 |
| household_v2 | 真实姓名、性别、出生年份、学历、婚姻、职业、电话、城乡、作息、地址 | OneToOne → auth_user |
| housing_info | 住房类型、面积、卧室数、客厅数 | ForeignKey → household_v2 |
| device_v2 | 设备类型、额定功率、购买日期、使用年限、损坏概率 | ForeignKey → household_v2 |
| income_info | 个人年收入、家庭年收入、收入来源、经济自评 | ForeignKey → household_v2 |

## 交互设计

注册界面采用Windows OOBE（开箱体验）风格设计。左侧为深色品牌面板，展示系统Logo、名称和六步进度指示器；右侧为白色表单面板，展示当前步骤的表单内容和进度条。界面采用左右分栏布局，视觉层次清晰，操作引导明确。窄屏设备自动切换为上下布局以保证可用性。

步骤指示器以圆形数字标记每一步，当前步骤高亮显示，已完成步骤显示绿色对勾，未完成步骤以灰色半透明状态呈现。每一步的表单底部设有"上一步"和"下一步"按钮，用户可自由前后浏览和修改已填写的信息。最后一步提交完成后显示成功动画，并在短暂延迟后自动跳转至首页。

## 管理员端同步

用户注册成功后，管理员可在数据管理界面的用户管理标签中立即查看新用户的所有信息，包括基本个人信息、住房情况、用电设备和收入状况。新用户同时出现在管理员知识图谱中，其能耗等级等画像标签将随着月度数据积累而逐步生成。
