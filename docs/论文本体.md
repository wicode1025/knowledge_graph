摘    要

在“双碳”战略及统一电力市场建设背景下，电力治理长期受制于异构数据的语义断裂问题，电力用户数据的深层挖掘极为不易。针对该问题，本文设计并实现了一个基于知识图谱的电力用户画像系统。
系统采用前后端分离的B/S架构，前端基于Vue3构建，利用ECharts实现数据可视化；后端基于Django框架提供RESTful数据通道。在存储层面，系统采用混合存储方案，利用MySQL存储用户信息与用电记录等结构化数据，利用Neo4j图数据库存储实体及关系，使用Cypher语句构建用户画像语义网络。同时，系统引入无监督机器学习中的K-Means聚类算法对用电行为数据进行分群挖掘，生成统计类、规则类和挖掘类标签体系。系统划分了前台用户与后台管理员双端模块，实现了电力数据的语义融合和直观的图谱可视化。黑盒测试表明，系统各项功能运行稳定，满足设计预期。

关键词：知识图谱，用户画像，Neo4j，K-Means聚类，Django
 
ABSTRACT

Under the background of the "Dual Carbon" strategy and the construction of a unified electricity market, power users are reshaping into "prosumers" who integrate power consumption and production. Traditional power governance models struggle to support refined energy management due to inconsistent data standards and a lack of semantic synergy. To address this issue, this paper designs and implements an electricity user profiling system based on knowledge graphs.
The system adopts a B/S architecture with front-end and back-end separation. The front-end is built on Vue3 and Vite, using ECharts for data visualization, while the back-end provides RESTful API interfaces based on the Django framework. In terms of storage, a hybrid storage solution is deployed: MySQL is used to store structured data such as user information and electricity consumption records, and the Neo4j graph database is utilized to store entities and relationships, constructing a user profile semantic network via Cypher queries. Concurrently, the K-Means clustering algorithm from unsupervised machine learning is introduced to segment electricity consumption behavior data, generating a label system consisting of statistical, rule-based, and mining-based labels. The system is divided into front-end user and back-end administrator modules, achieving semantic fusion of multi-source power data, intuitive graph visualization, and personalized refined energy governance. Black-box testing demonstrates that all functions of the system operate stably and meet the design expectations.

1.1研究背景及意义
1.1.1研究背景
能源作为支撑国民经济增长与社会进步的基石，其开发利用水平是衡量现代化水平的核心标准。步入21世纪以来，中国经济的高速增长带动了能源消费量的持续上升，长期依赖传统的化石能源的发电模式已经使能源与生态的矛盾日益凸显。2026年国务院下发的《碳达峰碳中和综合评价考核办法》[1]中首次提出将碳排放双控要求纳入党内的法规体系以推进我国“双碳”战略的执行。电能作为高效、清洁的二次能源，在政策影响下广泛应用于工业生产与民生保障的减碳行动中。然而，电力系统供需两侧的平衡面临巨大挑战，传统放管式的电力管理模式已经不适用于当前的电力市场，迫切需要通过数字化手段深度发掘用电侧的调节潜力。
国家层面，近年来出台的政策，为电力行业的数字化升级与需求两端的管理设定了明确目标。国务院办公厅在2026年4月发布的《关于更高水平更高质量做好节能降碳工作的意见》[2]中提出，要运用数字技术来改造传统产业，并且能源转型和降碳结合，推进新型电力系统的构建；在电力需求侧管理方面，国家发改委等联合印发的《关于深入推进供给侧结构性改革做好新形势下电力需求侧管理工作的通知》[3]中提出，通过信息和通信技术与用电技术的融合，推动用电技术进步，推动电力治理重心由“供给侧”向“消费侧”延伸。自2023年起，山西、广东等省份的电力现货市场转入长周期运行，电力现货市场的电价每15分钟就会更新一次[4]。传统的管理模式已经不适应这种快速变化的市场价格，也促使该行业向人工智能、大数据等前沿技术寻求解决方案。目前，国内主流电力企业已开始使用知识图谱来分析异构数据，试图去改变过去总账式的电量管理方法来满足如今精细化管理的需求。
在这一演进过程中，电力用户的角色发生了重大变化。随着越来越多的家庭和企业安装上了太阳能板等发电设备，电力用户一再只是消费者，而是转变为生成和消费为一体的“产销者”[5]。这种转变带来了治理层面的复杂挑战。相关研究表明，我国电力需求端正处于从“应急响应”向“常态化资源开发”的阶段，但是问题就在于一般用户家里的空调等小型电器数量虽然庞大，但是因为机制不通等问题无法连接上电网形成系统，产生数据孤岛问题[6]。这种“资源名义潜力大，实际有效水平低”的现象，其根源就在于各大电力业务系统之间数据结构不统一，有隔离性。因此，在全国统一电力市场背景下，通过知识图谱打破信息壁垒，已成为电力行业数字化转型的重点方向。
1.1.2 研究意义
本研究旨在探索电力数据由“简单标签”向“知识语义”升级。传统的电力用户画像方法只能大致了解数据的大小关系，但是新型电力系统中有海量且在不断动态变化的数据时，其往往是很难刻画出真实的语义关系的。知识图谱的本质是通过对电力实体、属性和实体之间的关系进行建模，连接成三元组，构建出具备逻辑推理能力的知识语义网络。将知识图谱引入到用户画像中，不仅能够深度挖掘产消者、电力设备与市场环境之间的关系，还能弥补传统统计模型在关系预测方面的不足。本研究提供了一套从数据分析到解析语义的系统开发实践，对于完善电力数字化转型的理论体系具有重要的探索价值。
1.2国内外研究现状
1.2.1 用户画像技术研究现状
电力用户画像是指通过收集和分析用户的属性特征、用电行为数据等，构建能够描述用户用电特征和行为模式的数字化模型。
国外研究方面，Wassie等利用非洲PV微型电网20个月的实测用电数据及238户用户调研数据，深入分析了不同类型用户的用电模式和消费特征[7]。研究发现，微型电网用户用电规律差别很大。不同用户类型、地区、时间的用电规律都不一样，特别是生产类型的用户，用电量是普通居民的三倍以上。Winzer等提出基于用户用电曲线的画像合同机制，利用匿名化智能电表数据分析不同对冲曲线对用户电费波动性的影响[8]。Ryu等提出基于RFM模型的两阶段聚类客户画像方法，首先利用RFM分析识别活跃且有价值的客户，其次分析其交易特征[9]。
在国内，王淇等利用电力大数据技术获取居民用电行为数据，构建了包含直观描述指标（日用电量、日平均负荷、日峰谷差）和比值描述指标（谷电系数、日负荷率、日峰谷差率）的居民用电行为分析指标体系[10]。郑朝芳针对用户用电行为数据规模大、维度高的特点，提出了基于大数据分析与用户用电行为模式的用户画像构建方法[11]。该方法利用K-means聚类算法挖掘用户用电行为模式，将行为模式挖掘结果与特征标签相结合生成用户画像。
赵晋泉等人提出了一种电力用户用电特征选择与行为画像方法，他们将最大最小冗余准则应用于用户画像用电特征选择，采用打分制对特征进行量化，最后通过雷达图和柱状图实现对电力用户行为画像的展示[12]。吴玉洁将知识图谱与用户画像技术相结合，基于霍尔三维系统结构构建差异化的用电偏好画像模型[13]。该研究从稳定度、偏好度、敏感度三个维度解读用户用电行为，实现对用户异常用电信息的识别。
1.2.2 知识图谱技术研究现状
知识图谱这个概念最早可以追溯到2012年Google提出的Knowledge Graph，初衷是为了让搜索引擎理解用户查询背后的语义。发展到现在，知识图谱已经从单纯的搜索增强工具演变成了一套完整的知识表示与推理体系。Hogan等人[14]在ACM Computing Surveys上发表了一篇很全面的综述，把知识图谱涉及的数据模型等技术点都梳理了一遍，是这个方向入门必读的文献。
从技术栈的角度来看，Biswas等人[15]专门梳理了知识图谱嵌入面临的各种挑战，比如怎么处理多模态信息，这些其实都还没解决得很好。另外Sardina等人[16]从图的本身出发，发现知识图谱的结构特性对嵌入模型的链路预测效果有不小的影响。在推理层面，DeLong等人[17]从神经符号AI的角度总结了目前的主流做法：一类是用逻辑规则来约束嵌入学习，另一类是从知识图谱里自动学出规则。
具体到电力这个垂直领域，知识图谱的落地应用这几年发展得很快。国外方面，剑桥大学的Kraft团队[18]搞了一套叫"The World Avatar"的动态知识图谱框架，用领域本体加语义Web技术来建模电力系统的脱碳路径。加拿大的Kor等人[19]提出了PowerLOV这个词汇表，在Neo4j上搭了一个超过200万个节点、1000多万条边的配电知识图谱GridKG，能支持停电影响仿真这类实际业务场景。意大利ENEA的Villani等人[20]则把知识图谱和GIS地理信息系统结合起来，用来评估气候变化场景下电力语义网络的韧性，实现了环境风险数据和电力基础设施数据的交流。斯洛文尼亚Jožef Stefan研究所的Hanžel等人[21]更进一步，整合了来自多个大洲20多个开源数据集，构建了一个RDF格式的居民用电知识图谱，做到了数据层面的整合。
蒲天骄和乔骥团队[22]系统性地梳理了电力知识图谱的研究，他们的综述覆盖了从构建技术到应用场景的研究情况。乔骥等[23]提出了一整套知识图谱框架，从CIM/E模型解析到知识抽取再到推理应用，每个环节都给出了实际方案。最近祁欣月等人[24]把关注点放在了事件知识图谱上，专门讨论电力调度场景下事件时序关系的建模问题。
在知识图谱和用户画像结合这个方向，郑斌青等[25]提出了一个融合知识图谱和改进FCM算法的电力用户聚类方法。陈新培[26]提出用户行为关联图加图卷积网络做居民用电行为识别，再配合图强化学习实现家庭能量管理决策。国网安徽的团队[27]把知识图谱拆分成知识元结构，再接入改进FCM做聚类，紧凑度等指标都有明显提升。吉涛等人[28]没有用FCM而是用改进的高斯混合模型和知识图谱配合，同样拿到了比K-Means和层次聚类更好的效果。这些工作有个共同的趋势：知识图谱不再仅仅是数据的组织方式，而是开始深度参与到聚类和画像建模的过程中。

2.1.1知识图谱概述
知识表示是人工智能领域的基础性研究课题，其核心任务是将人类知识转化为计算机可以理解并且可处理的形式化符号结构。从认知论的角度，知识是人们在长期生产实践和科学实验中形成的对客观世界的认知，数据是被记录下来的客观事实，信息是经过加工处理、具有决策价值的数据，其中知识反应的是数据之间的内在关联和因果规律。相对于数据和信息，知识的语义更加丰富，不仅可以描述“是什么”还可以回答“为什么”[29]。
谷歌于2012年首次提出了知识图谱的概念，其可以表示为G =（E,R,S）。其中， E表示实体，R表示关系，S表示三元组。本系统的知识表示即采用三元组的表示架构。系统使用RDF格式的三元组描述实体与关系的基本语义，节点表示用户、设备等实体，边表示拥有、归属等关系。

2.1.2 知识存储
知识图谱的物理存储需要了解图谱是由什么数据模型转化而来的。从数据结构角度而言，知识图谱本质上是图论中的图结构。在数学定义上，图被表示为G=(V, E)，其中V代表节点集合，E代表边集合。知识图谱数据模型以图论为基础，用节点表示现实世界中的实体对象，用边表示实体之间的语义关联关系，这种数据结构能够清晰地描述实体之间的语义关系。
知识图谱的存储方式有基于关系型数据库、基于资源描述框架和基于图数据库三类。
（1）基于关系型数据库的存储：该方案将知识图谱存储为关系表的结构。常见实现方式包括三元组表、属性表等。三元组表将每条三元组存储为一行记录，实现简单但面临多表自连接的性能瓶颈；属性表将同类主语分到同一表中，是对三元组表存储的优化。该方案的优势在于能够利用成熟的关系数据库技术，但查询时往往需要执行复杂的表连接操作，性能较差。
（2）基于资源描述框架的存储：资源描述框架（RDF）是用于表示语义网上关联数据的标准数据模型。一个RDF图被定义为三元组(s, p, o)的有限集合，其中s是主语，p是谓语，o是宾语，三元组(s, p, o)表示资源s与资源o之间具有联系p。RDF以统一资源标识符为实体赋予唯一标识，支持推理和查询。但RDF存储方案对于数据量大的实时查询性能有限，且更新操作通常只能以离线方式进行。
（3）基于图数据库的存储：图数据库属于非关系型数据库，数据基本单位是节点、边和节点属性。与关系型数据库相比，图数据库在处理复杂关系查询时具有显著的性能优势，特别适合关系推理和关联分析。Neo4j是目前应用最广泛的原生图数据库，基于属性图模型存储数据，每个节点维护着指向其邻接节点的直接引用，使得图遍历操作的代价仅与遍历范围成正比，而与图的总体规模无关。
故本系统采用Neo4j存储用户画像知识图谱。
2.2用户画像技术相关理论
2.2.1 用户画像概述
用户画像，即用户信息标签化，通过收集用户的基本信息、用电习惯、偏好特征等各个维度的数据，进而对用户特征属性进行刻画，并对这些特征进行分析、统计，挖掘潜在价值信息，从而抽象出用户的信息全貌。用户画像是电力企业分析数据的关键点，并作为研究个性化用电的前置条件，是非常关键的[30]。
随着智能电网的快速发展，用户画像技术已成为提升电网运营效率和服务质量的关键手段。在智能电网环境下，电力用户不再仅仅是电能的被动消费者，而是成为参与电网运行的主动角色。用户的一切用电行为在电力企业面前是可"追溯"、"分析"的。企业内保存了大量的原始用电数据和各种业务数据，这是电力经营活动的真实记录，如何更加有效地利用这些数据进行分析和评估，成为电力企业基于更大数据量背景的问题所在。随着大数据技术的深入研究与应用，电力企业的关注点日益聚焦在如何利用大数据来为精细化运营和精准营销服务，而要做精细化运营，首先要建立电力用户画像。
在电力行业，用户画像具有以下特点：（1）数据来源丰富，涵盖用电数据、设备数据、报装信息、缴费记录等多个来源；（2）用电行为具有时序性和周期性，便于挖掘用电规律；（3）用户群体差异明显，不同类型用户的用电模式存在显著差异。
2.2.2 标签体系分类
用户画像的建模其实就是对每一个用户“打标签”，从对用户打标签的方式上来看，分为三种类型：统计类标签、规则类标签和机器学习挖掘类标签。
（1）统计类标签：这类标签是最为基础的标签类型，例如，对于某个电力用户来说，其月用电量、日均用电量、峰谷用电比例、最大功率等字段可以从用户用电数据中统计得出。该类标签构成了用户画像的基础。
（2）规则类标签：该类标签基于用户行为及确定的规则产生。例如，对平台上"高耗能用户"这一口径的定义为"月用电量超过同类用户平均水平的150%"。
（3）机器学习挖掘类标签：该类标签通过机器学习挖掘产生，用于对用户的某些属性或某些行为进行预测判断。例如，根据一个用户的用电行为习惯判断其能耗等级偏好、预测用户的用电增长趋势等。该类标签需要通过算法挖掘产生。

2.3 K-Means聚类算法
2.3.1聚类分析概述
聚类分析是数据挖掘领域中的一种无监督学习方法，其基本思想是将数据集合中的样本划分为若干个簇。每一个簇中的样本都是高度相似的，不同的簇之间样本有明显差异。聚类分析区别于分类问题的重要特征在于：分类属于监督学习的范畴，训练使用到的数据是需要带标签的；而聚类分析属于无监督学习的范畴，分析时并不知道具体的类别结构，需要根据样本之间的相似性自行发现潜在的簇组织形式[31]。
从算法类型角度出发，聚类方法主要分为：基于划分的方法、层次聚类方法、基于密度的方法以及基于模型的方法。其中，基于划分的K-Means算法因实现简洁、计算高效等优势，成为应用及其广泛的聚类算法之一。
在电力用户画像研究领域，聚类分析具有重要的应用价值。通过对不同聚类群体的用电特征进行深入分析，管理者可以制定差异化的营销策略和服务方案。例如，针对高耗能群体提供需求响应管理服务，而针对低耗能群体则可挖掘潜在用电设备增加需求，预测用户增长潜力。

2.4.2 前端开发技术
Vue3框架是在2014年创建的开源JavaScirpt框架，其设计理念是逐步响应式的数据绑定与组合式视图组件。本系统采用Vue 3的Composition API进行组件开发。Composition API是Vue 3引入的核心特性，它允许开发者使用imported函数代替Vue 2中的Options API来构建组件。[32]这种组织方式的优势在于：组件代码复用更加方便、代码可读性更高等。在知识图谱可视化组件中，系统使用Composition API封装了图谱节点、边的连接、缩放拖拽等复用组件。
Vite是一个前端运行的工具。以前的前端启动工具得要先把整个项目的代码打包完才能运行，如果项目代码量大，启动工具延迟就会很长；而Vite的优点就是启动快，它用浏览器自带的模块化功能，做到按需编译，不需要打包整个项目，所以启动速度极快。
ECharts是由百度开源的数据可视化图表库，其具备多种图表模板，包括折线图、柱状图、饼图等，几乎涵盖了数据可视化的全部场景。在本系统中，ECharts承担了用电趋势分析、设备用电占比、聚类结果分布等核心功能模块的可视化任务。
2.4.3后端开发技术
Django是开源的Python Web框架，其核心组件包括：对象关系映射（ORM）系统、动态管理后台、URL路由系统、表单处理系统以及本地化部署。本系统利用Django的ORM系统实现了与MySQL数据库的交互，在kg应用中： models.py定义数据模型，views.py编写业务逻辑，urls.py配置URL路由。
2.4.3数据库技术
MySQL是开源的关系型数据库管理系统，目前属于Oracle公司旗下产品。MySQL使用结构化查询语言（SQL）进行数据库操作，支持多存储引擎架构，具有性能可靠、配置灵活、社区活跃等优点，是Web应用领域最流行的关系型数据库之一[33]。
本系统的MySQL版本为8.0，使用Django的MySQLdb驱动连接数据库，在Django settings.py中配置了数据库连接参数。系统的MySQL数据库命名为electric_user_profile，用于存储用户基本信息、用电数据记录、设备台账和聚类结果等结构化数据。
Neo4j是图数据库管理系统，其数据模型基于属性图模型构建的。属性图模型由节点、边、属性和标签四种基本元素组成，能够自然地表示现实世界中的实体及其关联关系。Neo4j的核心查询语言是Cypher，其语法类似于SQL但专门为图查询设计，支持模式匹配、聚合函数、路径查询操作。本系统的Neo4j版本为5.x，用于存储用户画像知识图谱数据。

3.1.2.2 安全功能需求

4.5 实现过程中的问题解决
（一）页面刷新后导航栏丢失问题
问题描述：本系统使用客户端持久化存储机制存储登录令牌，但是如果登录其他账号的时候，Vue的computed属性无法自动检测登录令牌的变更，导致管理员登录后的侧边栏仍然显示的是用户端的菜单栏。
问题解决：登录成功后使用window.location.href字段进行整页跳转，重新加载并读取持久化令牌，便可以解决该问题。
 
图 4 12 导航栏丢失问题解决代码
（二）表单重复提交问题
问题描述：在设备添加、用户注册等需要数据库写入的时候，若用户在提交请求尚未返回时快速点击提交按钮，浏览器会发出多个相同的 POST 请求，造成误触的效果，后端是无法识别这种重复性操作的，会导致写入的数据表中出现冗余数据。
问题解决：在提交按钮上绑定状态变量，然后添加 Vue 的 :disabled属性与按钮关联起来。点击提交时立即将状态字段设置为true，按钮变为灰色不可点击状态，同时按钮文字切换为"提交中…"；在请求完成后字段恢复为false。以此来保证用户不会重复提交表单。
（三）列表数据加载性能问题
问题描述：随着测试数据的几类，缴费历史等列表数据量增长导致页面加载变慢。
问题解决：后端在 Django ORM 查询层面对QuerySet 施加 Python 切片语法，其底层原理是将Python语句转换为 SQL LIMIT 子句，使数据库仅返回固定数量的最近记录，从源头控制单次查询的数据规模。前端侧通过计算属性提供按缴费状态和年份维度的筛选控件，用户可按需切换视图，避免一次性加载全部历史数据。

4.6 系统测试
系统测试是系统上线之前必要经历的环节，其目标是在系统投入使用之前将可能出现功能缺陷和逻辑错误找出来。我们会模拟正常情况和极端情况下的系统运行情况，检验系统不同条件下是否能够顺利工作，以这种方式来保证系统的可靠性。本系统的测试工作以用户实际使用场景为出发点，主要从用户端的登录与功能模块出发。 
系统测试方法主要分为以下两类：
（1）黑盒测试：测试人员在不了解系统内部实现细节的前提下，将系统的每一个功能依次运行，并同时关注系统能否可以正确处理事件并顺利完成工作，这一步叫做功能测试。该方法适用于检验相互、数据显示相关的功能。
（2）白盒测试：测试人员在掌握系统内部逻辑结构和代码的前提之后，按照程序的执行路径来设计测试用例，逐条得去排查每一个模块的代码是否运行成功，这一步叫做结构测试。这种测试方法会十分方便我们排查系统代码的Bug，同时对系统的流畅性也有很大提升。
本系统采用黑盒测试方法，模拟实际用户操作流程，在这个基础上对各功能模块进行逐一验证。

第5章	 结论
经过了前期的需求分析和系统设计阶段，以及后期的编码与测试过程，基于知识图谱的电力用户画像系统已经完成了设计开发的全流程，基本实现了包括用户注册与登录、个人信息维护、用电设备管理、月度电费缴纳、设备维修报单等用户端功能，以及知识图谱全局展示、数据管理和工单审核等管理端功能。
通过本次系统的设计与开发，让我对电力用户画像和知识图谱技术的实际应用有了深入的理解，在这其中，我的代码能力也得到了提升。在系统开发过程中，我步步遵循软件开发的基本流程，按照系统分析、系统设计、系统实现、系统测试的顺序逐步推进。在数据库设计方面，使用MySQL关系型数据库和Neo4j图数据库的结合是我针对该系统庞大的数据量想出的解决方案，这样可以满足结构化数据和图数据的存储查询的需求。在一些关键技术方面，每一个模拟设备用电、计费、维修的自动化流程的相关算法，JWT令牌和登录认证的相关技术都是我从网上学习得来的。在系统测试方面，采用黑盒测试方法对用户登录与功能模块进行了验证，测试结果也表明系统功能符合预期的设计要求。
但是我在开发这个领域上知识的经验都有欠缺，这个画像系统中仍然存在着一些不尽如人意的地方。就比如说每个月的模拟数据中对不同家庭用电行为没有能体现清晰的差异化；还有就是如果随着用户不断增加，知识图谱的体量也不方便展示了；数据库的设计是我自己设计并规划出来的结果，其是否具备真正的可用性还需要测试。
尽管系统还存在着种种不足之处，但从最初的理论分析、技术选择，到数据库的设计、前端界面搭建，再到知识图谱的构建与可视化呈现，每一个阶段都凝聚了我不断的思考。每当一个设想都变成实际的时候，让我感受到将理论转化为实践的成就感。
总而言之，通过本次毕业设计，让我将本科阶段所学的软件相关、数据库原理、前端等理论的知识有了一个完整的实战经验，同时也新学了图数据库这样之前没有接触的技术，让我体会到只有实战才可以提升自己的技术。开发过程中暴露出的问题也让我清醒地认识到自身能力的不足。本次毕业设计所积累的分析思路、技术方法和解决问题的经验，相信对今后的发展具有重要的参考价值。
