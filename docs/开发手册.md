# 电力用户行为画像知识图谱系统 - 开发手册

## 文档概述

本文档是基于系统设计文档（《功能规划报告.md》和《database_design.md》）编制的完整开发手册，整合了现有项目基础与系统设计文档的核心理念。本系统采用Vue 3 + Django REST Framework + MySQL + Neo4j技术栈，构建基于知识图谱的电力用户行为画像分析平台。

---

## 第一章 系统架构

### 1.1 整体架构

```
┌─────────────────────────────────────────────────────────────────┐
│                      前端展示层 (Vue 3 + ECharts)                │
├─────────────────────────────────────────────────────────────────┤
│  路由层 │ 状态管理 │ 组件库 │ 图表可视化 │ 网络请求(Axios)       │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│                      后端服务层 (Django REST Framework)          │
├─────────────────────────────────────────────────────────────────┤
│  认证模块 │ API视图 │ 业务逻辑 │ 数据处理 │ 序列化器             │
└─────────────────────────────────────────────────────────────────┘
                              │
              ┌───────────────┴───────────────┐
              ▼                               ▼
┌─────────────────────────┐     ┌─────────────────────────┐
│        MySQL            │     │        Neo4j            │
│  (结构化数据存储)        │     │   (图数据存储)           │
├─────────────────────────┤     ├─────────────────────────┤
│ • 用户基本信息          │     │ • 用户关系网络           │
│ • 用电记录              │     │ • 相似用户关系           │
│ • 设备信息              │     │ • 设备联动关系           │
│ • 统计汇总数据          │     │ • 用电模式图谱           │
│ • 聚类结果              │     │ • 聚类关系图             │
└─────────────────────────┘     └─────────────────────────┘
```

### 1.2 技术选型说明

**前端技术栈：**
- Vue 3：响应式前端框架，采用Composition API
- Vue Router 4：单页应用路由管理
- ECharts 5：数据可视化图表库
- Axios：HTTP网络请求库
- Vite 5：构建工具（开发服务器热更新）

**后端技术栈：**
- Django 4.2：Python Web框架
- Django REST Framework：RESTful API开发
- PyMySQL：MySQL数据库驱动
- neo4j-driver：Neo4j Python客户端
- NumPy/Pandas：数据处理

**数据存储：**
- MySQL 8.0：结构化业务数据存储
- Neo4j 5.x：图数据存储与关系查询

## 第二章 数据库设计

### 2.1 MySQL数据库设计

基于《database_design.md》的设计，进一步完善并结合当前项目实际需求。

#### 2.1.1 核心数据表

**用户信息表（users）**

存储用户基础信息和画像标签，是系统的核心实体表。

```sql
CREATE TABLE users (
    id INT PRIMARY KEY AUTO_INCREMENT,
    user_id VARCHAR(20) UNIQUE NOT NULL COMMENT '用户唯一标识',
    user_type ENUM('residential', 'enterprise') DEFAULT 'residential' COMMENT '用户类型',
    house_num VARCHAR(50) COMMENT '房屋编号',
    house_type VARCHAR(20) COMMENT '房屋类型',
    family_type VARCHAR(20) COMMENT '家庭类型',
    family_members INT COMMENT '家庭人口数',
    area DECIMAL(10,2) COMMENT '房屋面积(平方米)',
    province VARCHAR(20) COMMENT '省份',
    city VARCHAR(20) COMMENT '城市',
    district VARCHAR(20) COMMENT '区县',
    energy_level VARCHAR(10) COMMENT '能耗等级(极低/低/中/高/极高)',
    behavior_label VARCHAR(20) COMMENT '行为标签(节能型/正常型/波动型/高耗能型)',
    consumption_pattern VARCHAR(20) COMMENT '用电模式(早峰型/午峰型/晚峰型/稳定型)',
    total_kwh DECIMAL(12,2) DEFAULT 0 COMMENT '总用电量(kWh)',
    avg_daily_kwh DECIMAL(10,2) DEFAULT 0 COMMENT '日均用电量(kWh)',
    std_daily_kwh DECIMAL(10,2) DEFAULT 0 COMMENT '日用电量标准差',
    max_daily_kwh DECIMAL(10,2) DEFAULT 0 COMMENT '最大日用电量',
    min_daily_kwh DECIMAL(10,2) DEFAULT 0 COMMENT '最小日用电量',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_user_id (user_id),
    INDEX idx_energy_level (energy_level),
    INDEX idx_behavior_label (behavior_label),
    INDEX idx_consumption_pattern (consumption_pattern)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户信息表';
```

**日用电数据表（daily_consumption）**

记录每个用户每天的用电量数据，支持趋势分析和异常检测。

```sql
CREATE TABLE daily_consumption (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id VARCHAR(20) NOT NULL COMMENT '用户ID',
    date DATE NOT NULL COMMENT '日期',
    year_month VARCHAR(7) COMMENT '年月(YYYY-MM)',
    weekday TINYINT COMMENT '星期几(0-6)',
    total_kwh DECIMAL(10,2) COMMENT '日用电量(kWh)',
    is_holiday TINYINT DEFAULT 0 COMMENT '是否节假日',
    max_hour TINYINT COMMENT '用电最大小时',
    min_hour TINYINT COMMENT '用电最小时',
    peak_hours INT COMMENT '高峰小时数',
    INDEX idx_user_date (user_id, date),
    INDEX idx_date (date),
    INDEX idx_year_month (year_month),
    UNIQUE KEY uk_user_date (user_id, date)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='日用电数据表';
```

**小时用电数据表（hourly_consumption）**

记录每小时的用电数据，支持用电模式分析和时段特征提取。

```sql
CREATE TABLE hourly_consumption (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id VARCHAR(20) NOT NULL COMMENT '用户ID',
    date DATE NOT NULL COMMENT '日期',
    hour TINYINT NOT NULL COMMENT '小时(0-23)',
    kwh DECIMAL(10,4) COMMENT '小时用电量(kWh)',
    INDEX idx_user_date_hour (user_id, date, hour),
    INDEX idx_user_date (user_id, date)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='小时用电数据表';
```

**设备信息表（devices）**

存储用户拥有的电器设备信息及其功率参数。

```sql
CREATE TABLE devices (
    id INT PRIMARY KEY AUTO_INCREMENT,
    device_id VARCHAR(30) UNIQUE COMMENT '设备唯一标识',
    user_id VARCHAR(20) COMMENT '所属用户ID',
    device_code VARCHAR(20) COMMENT '设备编码',
    device_name VARCHAR(50) COMMENT '设备名称(中文)',
    device_name_en VARCHAR(50) COMMENT '设备名称(英文)',
    device_type VARCHAR(30) COMMENT '设备类型',
    rated_power INT COMMENT '额定功率(W)',
    daily_use_hours DECIMAL(4,1) COMMENT '日均使用时长(h)',
    INDEX idx_user (user_id),
    INDEX idx_device_type (device_type)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='设备信息表';
```

**FCM聚类结果表（fcm_clusters）**

存储模糊C均值聚类算法的结果，包括每个用户的隶属度。

```sql
CREATE TABLE fcm_clusters (
    id INT PRIMARY KEY AUTO_INCREMENT,
    user_id VARCHAR(20) NOT NULL COMMENT '用户ID',
    cluster_0 DECIMAL(5,4) DEFAULT 0 COMMENT '聚类0隶属度',
    cluster_1 DECIMAL(5,4) DEFAULT 0 COMMENT '聚类1隶属度',
    cluster_2 DECIMAL(5,4) DEFAULT 0 COMMENT '聚类2隶属度',
    cluster_3 DECIMAL(5,4) DEFAULT 0 COMMENT '聚类3隶属度',
    cluster_label VARCHAR(20) COMMENT '聚类标签',
    algorithm_version VARCHAR(20) DEFAULT 'v1.0' COMMENT '算法版本',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_user (user_id),
    UNIQUE KEY uk_user (user_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='FCM聚类结果表';
```

**用户标签表（user_tags）**

存储用户的多维度标签，包括静态标签和动态计算标签。

```sql
CREATE TABLE user_tags (
    id INT PRIMARY KEY AUTO_INCREMENT,
    user_id VARCHAR(20) NOT NULL COMMENT '用户ID',
    tag_type VARCHAR(30) NOT NULL COMMENT '标签类型(static/fcm_energy/fcm_behavior/seasonal)',
    tag_name VARCHAR(50) NOT NULL COMMENT '标签名称',
    tag_value VARCHAR(100) COMMENT '标签值',
    confidence DECIMAL(4,2) DEFAULT 1.00 COMMENT '置信度',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_user_type (user_id, tag_type),
    INDEX idx_tag (tag_name)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户标签表';
```

**相似用户关系表（similar_users）**

存储基于TransE嵌入计算的用户相似度关系。

```sql
CREATE TABLE similar_users (
    id INT PRIMARY KEY AUTO_INCREMENT,
    user_id VARCHAR(20) NOT NULL COMMENT '用户ID',
    similar_user_id VARCHAR(20) NOT NULL COMMENT '相似用户ID',
    similarity_score DECIMAL(5,4) COMMENT '相似度得分',
    similarity_type VARCHAR(20) COMMENT '相似类型(energy/behavior/comprehensive)',
    similarity_reasons TEXT COMMENT '相似原因',
    algorithm_version VARCHAR(20) DEFAULT 'v1.0' COMMENT '算法版本',
    INDEX idx_user (user_id),
    INDEX idx_similarity (similarity_score DESC),
    UNIQUE KEY uk_user_similar (user_id, similar_user_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='相似用户关系表';
```

### 2.2 Neo4j图模型设计

#### 2.2.1 节点类型

根据《功能规划报告.md》设计的实体体系，构建以下节点类型：

**User（用户节点）**
```
属性: user_id, user_type, energy_level, behavior_label,
      consumption_pattern, avg_daily_kwh, total_kwh
```

**Device（设备节点）**
```
属性: device_id, device_name, device_name_en, device_type, rated_power
```

**EnergyLevel（能耗等级节点）**
```
属性: level_name (极低/低/中/高/极高)
```

**BehaviorLabel（行为标签节点）**
```
属性: label_name (节能型/正常型/波动型/高耗能型)
```

**ConsumptionPattern（用电模式节点）**
```
属性: pattern_name (早峰型/午峰型/晚峰型/稳定型)
```

**TimeSlot（时段节点）**
```
属性: slot_name (早高峰/午间/晚高峰/夜间), hours
```

**Season（季节节点）**
```
属性: season_name (春季/夏季/秋季/冬季)
```

**FCMCluster（聚类节点）**
```
属性: cluster_id, cluster_label, user_count
```

#### 2.2.2 关系类型

| 关系类型 | 起始节点 | 结束节点 | 属性 | 说明 |
|---------|---------|---------|------|------|
| OWNS | User | Device | - | 用户拥有设备 |
| HAS_ENERGY_LEVEL | User | EnergyLevel | - | 用户所属能耗等级 |
| HAS_BEHAVIOR_LABEL | User | BehaviorLabel | - | 用户行为标签 |
| FOLLOWS_PATTERN | User | ConsumptionPattern | - | 用户遵循用电模式 |
| USES_AT | User | TimeSlot | avg_power, usage_count | 用户在某时段用电 |
| USES_IN | Device | TimeSlot | usage_ratio | 设备在某时段使用 |
| AFFECTED_BY | User | Season | seasonal_factor | 用户用电受季节影响 |
| SIMILAR_TO | User | User | similarity_score, based_on | 用户相似度 |
| BELONGS_TO | User | FCMCluster | membership | 用户属于某聚类 |
| HAS_TIP | User | Tip | tip_text | 用户有节能建议 |

### 2.3 数据同步策略

**写入策略：**
- MySQL：实时写入用户和用电数据
- Neo4j：每日定时同步用户关系和聚类结果

**查询优化：**
- 统计聚合查询：优先使用MySQL
- 关系路径查询：使用Neo4j
- 混合查询：根据业务场景选择最优方案

## 第六章 后端业务逻辑

### 6.1 核心服务模块

```
kg/
├── models.py          # 数据模型
├── views.py           # API视图
├── serializers.py     # 序列化器
├── urls.py            # 路由配置
├── fcm_service.py     # FCM聚类服务
├── embedding_service.py  # TransE嵌入服务
├── tag_service.py     # 标签生成服务
└── query_engine.py    # 图查询引擎
```

### 6.2 数据预处理流程

1. **数据加载**：从CSV/JSON加载原始数据
2. **数据清洗**：处理缺失值、异常值
3. **特征工程**：提取用户特征向量
4. **聚类计算**：FCM模糊聚类
5. **嵌入计算**：TransE知识图谱嵌入
6. **标签生成**：基于规则+聚类结果生成标签
7. **预计算存储**：缓存计算结果加速API响应

### 6.3 核心算法说明

**FCM模糊C均值聚类：**
- 输入：用户特征向量（能耗、行为、设备）
- 参数：聚类数=4，模糊因子=2
- 输出：每个用户的隶属度向量

**TransE嵌入：**
- 输入：知识图谱三元组
- 输出：实体和关系的向量表示
- 应用：相似用户计算
