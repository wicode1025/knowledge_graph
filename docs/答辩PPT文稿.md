## 第2页：研究背景 —— 为什么要做这个？

**政策驱动 + 行业痛点 = 迫切需求**

## 第3页：研究目标 —— 我要做什么？

**一句话：用知识图谱 + 聚类算法，构建电力用户画像系统**

三个核心任务：
1. **知识图谱构建**：将分散的电力数据组织成实体-关系语义网络
2. **用户分群挖掘**：用K-Means聚类对用电行为打标签
3. **完整系统落地**：实现用户端+管理端双端可用的Web系统

---

## 第4页：系统架构 —— 怎么设计的？

**B/S架构 + 前后端分离 + 混合存储**

| 层级 | 技术选型 | 职责 |
|------|---------|------|
| 前端 | Vue3 + ECharts | 页面渲染、图谱可视化、图表展示 |
| 后端 | Django + DRF | RESTful API、JWT认证、业务逻辑 |
| 存储 | MySQL + Neo4j | 结构化数据 + 图数据混合存储 |

- MySQL：用户、设备、用电记录等6张核心表
- Neo4j：实体-关系-属性三元组，Cypher图查询

## 第5页：标签体系与聚类 —— 画像怎么生成？

**三级标签 + K-Means分群**

```
统计类标签 → 规则类标签 → 挖掘类标签
（月用电量）  （高耗能判定）  （K-Means聚类）
```

K-Means聚类流程：
1. 提取6维用电特征（日用电量、日负荷率、峰谷差率等）
2. 无监督分群 → 划分能耗等级
3. 生成画像标签：能耗等级 + 行为特征 + 用电模式

→ 从"数据"到"标签"再到"语义知识"

## 第8页：实现难点与解决

三个典型工程问题：

| 问题 | 解决方案 |
|------|---------|
| 登入切换后导航栏不更新 | `window.location.href` 整页强制刷新 |
| 表单重复提交产生冗余数据 | Vue `:disabled` 状态绑定 + 提交中锁定 |
| 列表数据量大加载慢 | Django ORM切片 → SQL LIMIT + 前端筛选控件 |
